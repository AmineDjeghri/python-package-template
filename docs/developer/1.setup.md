# 1. Setup

Get a working development environment.

## Prerequisites

| Tool            | Version                                  | Needed for                                      |
|-----------------|------------------------------------------|-------------------------------------------------|
| make, bash, git | Linux, macOS or Windows (Git Bash / WSL) | everything                                      |
| uv              | recent                                   | everything; `make install-uv` installs it       |
| Python          | >= 3.12(`requires-python`)               | everything; uv downloads it when missing        |
| gh CLI          | any                                      | releasing from a laptop (`make release`)        |
| Docker          | any                                      | optional: developing in a container, `make act` |

## Install

```bash
git clone https://github.com/AmineDjeghri/python-package-template.git
cd python-package-template
make install-dev          # .venv with the package (editable), dev and docs tools
make pre-commit-install   # git hook: the checks run on every commit
cp .env.example .env      # optional: LOGGING_LEVEL and your own settings
make test-installation  # builds the wheel, installs it in a clean env, loads hello
make test-all                 # everything is green
```

`uv pip install -e .` also works in an environment you manage yourself (venv, conda...).

## GitHub login (once, only to release)

```bash
gh auth login             # github.com, HTTPS, browser login
```

`make release-version` uses that login; nothing to put in `.env`. See [5. Release](5.release.md#credentials).

## Develop in a container (optional)

| Command             | Does                                                             |
|---------------------|------------------------------------------------------------------|
| `make docker-build` | builds the `python-package-template` image from the `Dockerfile` |
| `make docker-prod`  | runs it with a shell                                             |
| `make docker-dev`   | runs it with the project mounted in `/app`                       |

Inside the container: `make test-smoke-cli` and `make test-all`. If a local `.venv` conflicts with
the mounted one, delete the local one (`rm -rf .venv`).

## Run the GitHub Actions locally (optional)

`make install-act`, then `make act` (Docker must be running).

## IDE

- Interpreter: `.venv/bin/python`.
- PyCharm: mark `src` as Sources Root and `tests` as Test Sources Root, so imports resolve.
- `.editorconfig` sets indentation and line endings (tabs in `Makefile` and `*.mk`).

`make help` lists every target.

## Comprehensive software validation

`make test-all` is the required comprehensive software check for users, developers and CI.
This template currently has no integration suite or live-service credential requirement. Future
integration suites must join this command; see [the testing guide](4.testing.md) for the current suite scope. A focused
`make test-local` pass does not
establish full validation. Missing services or skipped integration must be reported as incomplete.
Coverage and artifact/runtime checks remain explicit alongside this command.
