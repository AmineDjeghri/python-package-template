# 1. Setup

Prepare the package, development tools and documentation environment.

## Prerequisites

Make, Bash, Git and uv on Linux, macOS or Windows with Git Bash/WSL.
uv uses or provisions a Python interpreter; run `make install-uv` if uv is missing.

## Install

```bash
git clone https://github.com/AmineDjeghri/python-package-template.git
cd python-package-template
make install-dev
make pre-commit   # static checks and hooks
make test-all     # tests
make docs-build   # strict documentation build
```

`make check` runs all three at once (and first warns if the Git hooks are missing).

This creates `.venv`, installs the editable package, the development/docs tools and, in a Git checkout,
the Git hooks, then validates the checkout. No integration service or credentials are needed.
Optionally copy `.env.example` to `.env` to customize settings such as `LOGGING_LEVEL`.

## Run

```bash
make run
```

This runs the greeting example.

## Documentation site

```bash
make deploy-doc-local
```

## Everyday commands

| Command                 | Use                                                                |
|-------------------------|--------------------------------------------------------------------|
| `make check`            | The full local gate before a pull request                          |
| `make test-local`       | Self-contained tests only                                          |
| `make pre-commit`       | Run the static hooks; `FILES="path/a path/b"` limits them to files |
| `make docs-build`       | Strict documentation build                                         |
| `make deploy-doc-local` | Preview the documentation site                                     |
| `make clean`            | Remove caches and temporary files                                  |
| `make help`             | List all targets                                                   |

## Optional environments and tools

| Command                | Use                                                                            |
|------------------------|--------------------------------------------------------------------------------|
| `make install-prod`    | Production dependencies only                                                   |
| `make install-tools`   | Quality and docs tools without the application dependencies                    |
| `make install-release` | Packaging and release tools without the application dependencies               |
| `make update-uv`       | Update an existing uv installation                                             |
| `make act`             | Run GitHub Actions locally (`make install-act` first; needs Docker and `.env`) |
| `make docker-build`    | Build the development image                                                    |
| `make docker-dev`      | Open a container with this project mounted in `/app`                           |
| `make docker-prod`     | Open a shell in the built image                                                |

The Dockerfile currently calls `make install-dev` without first installing uv; install uv
in the image before that step to use these Docker targets. Inside the container, use
`make run` and `make check`. `docker-dev` uses a separate volume for `/app/.venv`.
A manually managed environment can use `uv pip install -e .`; that alone does not install
the development tools. For publication, see [release credentials](5.release.md#credentials).

## Editor and agent rules

Select `.venv/bin/python`; mark `src` as Sources Root and `tests` as Test Sources Root.
Follow `.editorconfig` for indentation and line endings.
Agent rules live in `AGENTS.md`; `CLAUDE.md` links to it for Claude Code.
Edit `AGENTS.md` to update the shared instructions.

`make help` lists all targets. Next: [Conventions](3.conventions.md) and [Testing](4.testing.md).
