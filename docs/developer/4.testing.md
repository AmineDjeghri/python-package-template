# 4. Testing

`make test-all` is the required comprehensive software check for users, developers and GitHub Actions.
Run it before reporting that the software is fully validated. It runs the self-contained suites first,
then real-service integration tests where a suite exists. `make test-local` remains a focused diagnostic
shortcut; passing it does not establish full validation. The ambiguous `make test` target is removed.

Keep static quality, coverage reporting and artifact/runtime checks explicit alongside software tests.
`make check` combines static checks, `make test-all` and strict documentation validation. It can call
real services. `make help` lists focused commands and their requirements.

The comprehensive command does not accept per-suite `ARGS` filters; use focused targets for selected
tests. Worker-count options remain available.

## Required checks

```bash
make install-dev
make test-all
make pre-commit
make docs-build
```

This template currently has unit tests and no integration suite. `make test-all` runs every existing
software test, and CI explicitly reports that integration coverage does not yet exist. Add future
integration suites to `test-all`; never silently omit them or claim they ran. Empty test selections fail.

`make test-unit` and `make test-local` are focused commands. Use `make test-all N=8` to change worker
count. `make test-installation` (alias `make test-smoke-cli`) builds the wheel, installs it in a throwaway
`uv run --isolated --no-project` environment and loads the `hello` console script; it is not part of
`make test-all`. Coverage reporting is not currently configured.

GitHub Actions and both release branches invoke `make test-all`. Its always-running summary records
complete or incomplete software validation, including setup failures where tests never start.

## Writing tests

- One file per module: `tests/test_<module>.py` (the `name-tests-test` hook checks it).
- Tests run in parallel: no shared state. Use `tmp_path` for files and `monkeypatch` for
  environment variables (see `tests/test_settings.py`).
- Async tests: `pytest-asyncio` in strict mode, mark them with `@pytest.mark.asyncio`.

## What `make pre-commit` checks

| Hook                         | Checks                                                                                                                  |
|------------------------------|-------------------------------------------------------------------------------------------------------------------------|
| pre-commit-hooks             | large files, TOML/YAML/JSON syntax, end of file, trailing whitespace, merge conflicts, LF line endings, test file names |
| ruff, ruff-format            | lint (docstrings, unused imports) and format                                                                            |
| detect-secrets               | no credential in a file                                                                                                 |
| uv-lock                      | `uv.lock` matches `pyproject.toml`                                                                                      |
| markdownlint-cli2, codespell | Markdown style and spelling                                                                                             |
| properdocs build --strict    | the documentation builds, no broken link                                                                                |
| commitizen (on commit)       | commit message format                                                                                                   |
