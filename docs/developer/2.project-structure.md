# 2. Project structure

Where things are, and where to add yours.

## Layout

```text
src/python_package_template/
  example.py            example module, console script `hello`
  settings.py           ApplicationSettings (pydantic-settings) and the loguru logger
tests/                  one test file per module (test_<module>.py)
docs/
  developer/            this guide
  examples/             example scripts, rendered as pages by scripts/gen_example_pages.py
  images/               logo and screenshots
scripts/
  emoji_commit_parser.py  semantic-release parser that accepts a leading emoji
  gen_doc_stubs.py        API reference pages from package/workspace source directories
  release_artifacts.py    Git release tags and complete wheel/sdist checks
  gen_example_pages.py    pages from docs/examples/*.py
makefiles/              one .mk per concern, included by Makefile
.github/                workflows, composite actions, Renovate, issue and PR templates
Dockerfile              development / production container
properdocs.yml          documentation site (MkDocs Material)
CHANGELOG.md            written by semantic-release, never by hand
```

## Add a module

1. Add `src/python_package_template/<module>.py`, with Google-style docstrings: they become the
   API reference page automatically.
2. Add `tests/test_<module>.py`.
3. Log with the package logger: `from python_package_template.settings import logger`.

## Add a setting

1. Add a field to `ApplicationSettings` in `settings.py`:

    ```python
    EXAMPLE_ENDPOINT: Optional[str] = Field(default=None, description="the endpoint")
    EXAMPLE_API_KEY: Optional[SecretStr] = Field(default=None, description="the api key")
    ```

2. Set it by environment variable or `.env`; add it, empty or with a safe default, to
   `.env.example`.
3. Secrets are `SecretStr`: read them with `.get_secret_value()`; they print as `**********`.

## Add an example

Drop a `.py` file in `docs/examples/`. Its module docstring becomes the description on the
Examples page.
